## Proposed experiment
Twelve newly authored deterministic Python programming tasks across dependency scheduling, interval operations, event state reduction, record reconciliation, parsing, and bounded resource allocation. Use explicit public specifications and examples, separately authored held-out tests, and a reference implementation. The author of tests must not implement evaluated solutions. Validate reference solutions against all tests and demonstrate mutation sensitivity before running models. Freeze public specifications and hidden tests with SHA-256 hashes before the first scored call. Tasks with inconsistent specifications are excluded only through a documented amendment before outcomes are inspected.

Three arms receive identical public specifications:
1. Single: one Luna Max implementation attempt.
2. Self-revision control: the identical initial implementation followed by one fresh Luna Max self-review/revision call with the public spec and initial code, without held-out feedback.
3. Beastmode: the current director produces an acceptance/implementation plan from public specifications only; Luna Max implements; director reviews code against the public contract; Luna Max makes at most one revision. Hidden tests are unavailable to director review and all evaluated model calls.

The initial single output is intentionally shared with the self-revision arm, enabling a paired incremental comparison; it is not an independent sample. Beastmode initial outputs are separately generated because the director plan is the intervention. The self-revision control matches the number of executor calls, not total tokens or director computation. Do not label this a compute-matched causal estimate. Report measured usage for every available call and separately disclose director overhead that cannot be attributed per task.

This first study assesses a concrete manual Beastmode workflow on bounded coding tasks, not all adapters or general production development. A null outcome is publishable. Do not call a prompted role-play or replay of fixed patches a live Beastmode experiment.

Run two repetitions per task and arm (24 task/repetition units; 72 final artifacts, with shared baseline/control initial calls). Freeze task order and arm order using seed 20260911 before execution. Repetitions are clustered within task; 12 tasks, not 24 or the number of assertions, are the independent generalization units. No optional stopping for favorable results. Infrastructure failures remain visible, with at most one logged retry of the same call; never restart a live call merely because polling timed out.

## Outcomes and analysis
Primary: task solved (all held-out checks pass) per arm, averaged over repetitions within task. Secondary: fraction of held-out checks passed, syntax/runtime failures, elapsed time, observed input/cached/output/reasoning tokens, and repair regressions. Costs in dollars only if authoritative pricing and billing units are verified; unavailable fields remain unavailable.

Report paired differences for Beastmode versus each control, per-task outcomes, cluster bootstrap 95% intervals with seed 20260911 and 10,000 task resamples. With 12 task clusters these intervals are exploratory; no broad superiority claim based solely on point estimates. Include both repetitions, failures, missingness, and negative outcomes. A later confirmatory study requires an independently authored or external task sample and a new frozen protocol, not post-hoc extension until significance.

## Isolation and provenance
Evaluated economy-worker calls emit solution code only and receive no grader, reference, other-arm solution, or private run directory. Reject/audit any evaluated call that uses tools to inspect hidden data. Run candidate code in a bounded isolated process with no secrets/network; record the isolation boundary accurately. Retain exact prompts, final outputs, timestamps, requested model/reasoning, runtime serving-model evidence where exposed, and usage. Self-reported model identity is insufficient. Missing attestation means unverified, not validated.

## Operational amendment A — before any scored trial

The estimand is the quality difference between these complete recorded workflows on this fixed task suite, not a compute-controlled architectural effect. There are 24 paired task/repetition blocks (12 x 2), 72 final arm outputs (24 x 3), and exactly 96 planned economy calls (24 x 4). The four call stages are single, self_revision, beast_initial, beast_revision. Both revision calls always occur; even a review finding no defect asks the worker to return the complete verified code. The final Beastmode artifact is always beast_revision, never whichever candidate scores best. Single and self_revision intentionally share the single initial call. Two director reviews per task apply separately to the two Beastmode initial outputs; one precomputed public-only plan per task is shared across repetitions. This amendment supersedes 'at most one revision' above.

All director plans are fixed before candidate generation. Director reviews use only public specification, plan, and that Beastmode initial output; the director does not inspect baseline candidates or any held-out scores until all reviews are complete. No model receives another arm's output except the explicitly shared Single -> Self-revision dependency. Held-out scoring begins only after every planned final artifact is frozen. Review prompts and decisions are retained. Workers constructing tests never implement or repair evaluated candidates.

Use Python's random.Random(20260911): create task01..task12 in ascending order, repetitions 1 then 2 per task, shuffle those 24 blocks once, then independently shuffle ['baseline','beastmode'] for each block. Baseline executes single then self_revision; Beastmode executes beast_initial then beast_revision with director review between. Run serially (concurrency one) for scored model calls. Retain the generated schedule as authoritative so reproduction does not depend on an unspecified RNG implementation version. Record Python version. No outcome-based reordering.

The frozen manifest includes schema_version, UTC timestamp, base Git revision, protocol hash, task IDs, repetitions, arm/stage lists, full schedule, SHA-256 and relative path for every public spec/example, private case file, reference, mutant, fixture validator, harness/test, fixed prompt template, and director plan. Mutable result files are excluded. Every invoke/score checks the hashes and refuses changed inputs. Amendments require a new run identifier, documented reason, and retained old run. No amendments after inspecting outcomes of this planned study.

Economy configuration is the OpenAI Codex account lane, model gpt-5.6-luna, reasoning max, native codex exec, read-only agent sandbox, no model tool use permitted by the trial contract. Persist CLI version, requested configuration, full task prompt, and runtime turn_context model/effort evidence per call; snapshot/build identifier and server-side sampling limits are unavailable unless the runtime exposes them. Persist the common system/developer configuration digest where exposed without credentials. Do not claim model identity beyond the strength of client runtime evidence. The current director session identity is recorded from its runtime context when available; proprietary backend snapshot identity is not independently attested. No automatic model changes. Token usage is observed, not budget matched. An individual economy call has a 600-second execution limit; exceeding it is a model-call timeout with original output retained. Observation timeout is not execution timeout.

A successful final output must contain exactly one Python module (optional single surrounding Markdown code fence), expose solve, use no model tools, and have matching runtime model/effort evidence. Missing output, forbidden tool use, missing/mismatched provenance, syntax error, candidate exception, candidate timeout, and wrong answers each remain a reported outcome category. Unverified model artifacts are excluded from validated-quality claims but count as unsolved in the full planned denominator. Report both artifact quality and evidence validity separately. Token and monetary costs remain unavailable where not measured; never substitute estimates silently.

Scoring mounts only the candidate and minimal interpreter/runtime into a bubblewrap namespace with --unshare-all, a scrubbed environment, private /tmp, no host home, and no grader/reference/expected-output file. Inputs are passed over stdin; expected outputs remain in the parent. Require 256 MiB address-space limit, 2-second CPU limit and 5-second wall limit per case, bounded stdout (1 MiB) and zero tolerance for extra/non-JSON output. If platform limits cannot be applied, stop before scored evaluation and amend the unrun protocol; no unsafe fallback. Score each case independently to avoid cross-case state. JSON equality must preserve scalar type distinctions (especially bool versus int), object key order is immaterial, array order matters, and numeric values otherwise compare mathematically. Report per-task fraction of cases passed, then average tasks and repetitions equally; do not pool assertions as independent observations.

Each reference passes every public and held-out case. Each task has at least two plausible distinct mutants and every mutant must fail at least one held-out case. An independent checker audits public/hidden semantic consistency without showing held-out material to the director. Mutation sensitivity is necessary but not proof of test completeness.

Only pre-response infrastructure failures (launch failure, provider transport failure without candidate output) qualify for one identical retry. Retain both records and charge all measured usage/time. Candidate failures, low scores, tool misuse, and model/provenance failures do not qualify. Missing cells remain unsolved in the fixed 24-per-arm denominator and are enumerated separately; never use only complete cases for the headline rate. Scorer infrastructure failures stop analysis until resolved, without being confused with wrong candidate answers.

For each task, average the two binary solve outcomes per arm. The primary arm score is the mean of the 12 task averages. For each contrast, compute its paired per-task differences and their mean. Bootstrap 10,000 samples of 12 task indices with replacement using seed 20260911, preserving all arms and both repetitions within each selected task; use percentile bounds at 2.5% and 97.5% with linear interpolation. Report the full 12 differences and warn when the interval degenerates. No equivalence claim, p-value or significance stopping rule. Repair regression is initial solved -> final unsolved within that workflow; score stored initial Beastmode artifacts only after director reviews are finished.
